# 性能压测与优化记录

2026-11-06，本机 Windows x64 / Intel i5-14600K / Node v24.18.1。基线为 `200ef37`（0.1.0），优化数据来自压测时尚未发布的工作区，随后优化已纳入 npm 0.1.1；不是重新下载两个 npm 包的线上版本对比。0.1.2 后续加入会话名称和跳转元数据，本报告未对该新增路径重新压测。无运行时第三方依赖。

## 复现

```bash
npm ci
npm run bench -- --long > bench/current.json
```

直接用 `node --expose-gc bench/performance.ts --long` 可避免 npm 的脚本提示混入 JSON。去掉 `--long` 可跳过较久的离线积压场景。脚本仅监听 `127.0.0.1` 随机端口、使用临时配置，不修改真实 Pi 配置，不发送到真实通知服务。基线与优化各运行一遍完整场景，原始数据见 [baseline.json](baseline.json) 和 [optimized.json](optimized.json)。

- 统计发送入队耗时、端到端延迟、成功/丢弃/失败、CPU、事件循环延迟、堆/RSS；目标串行、不同目标并行。
- 连续负载按每 50 ms 入队 10 条规划；Windows 定时器导致实际约 1.2 秒入队 200 条，而非精确恒定 200/s。
- 突发同时入队 1000 条，验证 100 条上限，不是承诺无损吞吐。
- 消息微基准复用 128 块 × 8192 字符的 1 MiB 文本，预热后连续处理 500 次；测量扩展额外处理，不是模型生成、SDK 或整个会话内存。
- 堆峰值每 10 ms 采样，可能漏掉瞬时峰值；消息微基准报告循环前后堆差。GC、CPU 频率、其他进程和 Windows 计时粒度影响数据，不能当跨平台 SLA。

本机健康小请求延迟下降来自改用原生 `node:http` / `node:https`。另做 100 条顺序本地请求对照：fetch 约 1.3–1.5 秒，原生 HTTP 约 34 ms；两者均复用连接，不能简单归因为“以前每次都新建连接”。不能推断其他 Node 版本或操作系统也有同样倍数。

入队增加隐私裁剪和生命周期记账，健康负载下 p99 从约 10 µs 增至 47 µs，仍是非网络等待的微秒级操作。优化不是每一个局部指标都下降。

网络拒绝连接、HTTP 503、请求挂起三个场景均完成；保持有限重试、超时和约 1.2 秒的显式关闭宽限，未让坏目标阻塞另一个健康目标。正常关闭默认宽限仍为 2 秒。健康持续场景的采样堆峰值增量由 15.681 降至 12.275 MiB，GC 后增量由 3.263 降至 1.437 MiB；短时观测不能证明长时间零泄漏。

## 具体优化

1. 只有有效目标启用正文且订阅 completed/error/cancelled 才读取回复；只复制前 2000 字符，跳过剩余文本与思考块。不为无订阅事件构造通知。
2. HTTP(S) 原生 keep-alive；字节级 Content-Length；不重定向，不保存响应正文。小响应排空用于连接复用，超过 64 KiB 中止正文消费；错误/慢正文受取消和超时保护。
3. 每个目标 100 条、所有新旧目标合计最多 16 个队列。队列空闲后移除 Map 项，配置反复改名不无限保留空队列。
4. 队列事件从本地入队起预算 30 秒，包含请求和重试。待发过期丢弃，活动请求到预算取消。使用单调时钟，及时清理请求和事件定时器。不是实时系统：暂停/休眠会推迟定时器，已经送达的请求也无法撤回。
5. 入队前按目标移除正文/目录，仅保留所需发送配置，减少积压中的敏感数据与无关配置引用。
6. 增加 delivered/pending/expired；关闭未开始的积压也计入 dropped。基线未统计关闭时放弃的排队事件，因此不能直接拿新旧 dropped 差值当性能退化；例如离线场景基线 dropped 99，优化 dropped 196，后者包含关闭丢弃。

`npm run check` 与 15 项测试通过，包括订阅/隐私、固定重试 ID、401 不重试、跨地址重定向不跟随、超时/关闭取消、独立目标、并发队列上限、正文懒读取/截断/配置重载、空队列释放、过期后恢复、新旧目标总上限、UTF-8 字节长度/连接复用/大响应截断、截断响应失败回收。

## 保留的边界

- 慢接收端仍会丢弃；不做持久化、不无限扩容、不并发打乱同目标事件顺序。50 ms 延迟场景仍丢 82/200 条，属于主动保护，不是“完全解决背压”。
- 30 秒过期保护用及时性换完整性，不能用于账务、审批或必须送达的任务队列。等待/恢复等状态事件也可能丢失。
- 超时后重试可能重复送达，接收端必须按事件 ID 去重；不保证 exactly-once。
- 内存与吞吐测试针对扩展及模拟 HTTP 接收端，不涵盖 Pi 模型生成、网络公网抖动、整个 UI 渲染或其他插件。
- npm 0.1.1（性能优化）和 0.1.2（会话元数据）已发布；后续发布仍需独立验证 npm 包。引用固定旧提交的离线安装方也需要更新来源版本与文件完整性清单，不能只加新模块却遗漏安装清单。
